📁 E2E Tests – Angular File Tree (Selenium + C# + NUnit)

📌 Project Overview

This repository contains automated End-to-End test for an Angular application presenting a nested file tree.

The goal of this project was to:
- implement a clean Page Object architecture,
- expand a file path programmatically (/home/user/projects/README.md),
- generate a screenshot of the expanded tree,
- compute and verify a checksum based on the file name,
- provide a readable HTML test report,
- ensure cross-platform execution (macOS & Windows).


🏗 Architecture

Key architectural decisions:
- Page Object Pattern – separation of page logic from test logic.
- Component abstraction (FileTree) – tree interactions encapsulated and reusable.
- Recursive path expansion – no loop used to expand segments.
- Explicit waits only – no hard sleeps.
- DriverFactory – centralized WebDriver configuration.
- Checksum validation (SHA256) – additional functional validation beyond UI.
- HTML report generation (TRX → ExtentReport).


🧪 What the Test Does

The main E2E test:
1. Opens the Angular application.
2. Expands the root (/) if present.
3. Recursively expands path presented in task: home → user → projects → README.md
4. Verifies:
- page title,
- tree visibility,
- folder expansion state,
- file name read from UI,
- SHA256 checksum of the file name.
5. Generates a screenshot of the expanded tree (which can be found in tests-selenium/UiTests/TestResults/).
6. Produces an HTML report.


🚀 Running the Tests

1. Prerequisites:

- Node.js
- .NET SDK (10+)
- .NET 8 Runtime (required for HTML report generation)
- Google Chrome

2. Install dependencies: npm install

3a. Run application + E2E tests
- macOS / Linux: APP_URL=http://localhost:4200 npm run e2e
- Windows (PowerShell): $env:APP_URL="http://localhost:4200"; npm run e2e

3b. Run application + E2E tests + HTML report
- macOS / Linux: APP_URL=http://localhost:4200 npm run e2e:report
- Windows (PowerShell): $env:APP_URL="http://localhost:4200"; npm run e2e:report

In this case 📊 test report is generated at tests-selenium/test-report/ExtentReport.html

4. Open report in browser to see:
- Pass / Fail status
- Execution time
- Stack traces (if any)


🖥 Cross-Platform Support

The project is designed to run on:

✅ macOS (including Apple Silicon)
✅ Windows

Key cross-platform considerations:
- APP_URL passed as environment variable.
- Chrome launched with --force-device-scale-factor=1 in order to avoid Retina / DPI scaling inconsistencies.
- No OS-specific paths.
- No hardcoded absolute directories.
- Screenshot handling designed to work consistently across macOS and Windows.


🔍 Technical Decisions

1️⃣ Selenium + C#
- Chosen for strong typing, mature ecosystem, and integration with .NET reporting tools, as well as due to experience gained in recent projects.

2️⃣ NUnit
- Lightweight, readable assertions, widely adopted in .NET QA environments.

3️⃣ TRX → Extent HTML report
- TRX generated by dotnet test
- Converted to Extent HTML via TrxToExtentReport
- Clean and readable test summary for stakeholders

4️⃣ Explicit Wait Strategy
- Avoided Thread.Sleep.
- Used WebDriverWait with visibility and state checks.

5️⃣ Screenshot Strategy
- Element-level screenshot
- Chrome launched with --force-device-scale-factor=1
- Ensures consistent behavior on Retina and high-DPI displays
